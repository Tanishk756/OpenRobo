# Product Requirements

## P0 — Must have
- Global robotics resource registry
- Search and filtering
- Domain/category taxonomy
- Standardized resource metadata
- Source repository and documentation references
- SPDX license identifiers
- Dependency representation
- Platform/architecture compatibility
- Resource submission and validation
- Public API
- CLI
- Local-first operation
- Responsive web UI
- Open-source repository and contribution workflow

## P1 — Required foundation
- Compatibility graph
- Stack builder
- Stack export
- Reproducible environment specification
- GitHub ingestion
- Health/activity signals
- Hardware/software relationship modeling
- Simulation metadata
- Security scanning hooks
- SBOM-aware architecture

## P2 — Expansion
- Workspace generation
- Simulation launch integration
- Benchmarking
- Community discussions
- AI assistant/RAG
- Local model support
- Cloud execution as optional infrastructure
- Advanced fleet/deployment integrations

## Acceptance principle
Every feature must have a testable acceptance criterion and must not silently violate the open-source, free, vendor-neutral, or local-first principles.
